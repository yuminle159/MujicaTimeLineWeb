# 日文访谈翻译与排版规则

## 一、目标与参考标准

将[original][/original]之间的日语文本完整翻译成中文，替换它上方的占位符（中文）。目标是可以直接刊登的中文访谈：信息准确、阅读顺畅，并保留说话人的声音。

忠实的是信息、逻辑、语气和表达意图，不是日语语序。允许并要求润色中文表达；不允许添加原文没有的事实、解释、评价和情绪。

用户认可 `_data/mc/` 中已有的人工校对译文，但明确排除 `261109Billboard-Diggy-MO前篇.md`，不得用它提炼风格或作为质量范例。参考文件中的“（中文）”占位不属于译文样本，只有标题译完的文件也不能作为正文风格依据。未要求重译时，保留已有人工校对内容，不据此批量改写历史文章。

翻译前按内容选择参考，阅读完整的中日文对照问答：

- 成员对谈参考 `20250117lisani弄结访谈.md`：接话简洁，情绪自然，允许短句、停顿与感叹，不把每个回答扩写成完整论述。
- 创作访谈参考 `dgm元素.md`：保留思考、转折和自我修正，专业内容表达清楚，不把复杂论述概括成泛泛感想。
- 乐曲解说参考 `250328dgm完满.md`：保留原文确有的隐喻、概念密度和诗性，不为去除翻译腔而一律口语化。

## 二、翻译与中文表达

- 准确性优先。忠实保留原文的信息、语气、逻辑关系和表达强度，不遗漏重要信息，也不要增加原文没有的含义。

- 中文自然度同样重要。不要拘泥于日语原句的语序和句法，可以根据现代中文的表达习惯调整语序、拆句、合句、补足必要的主语或省略中文中多余的成分。

- 可以充分调整中文表达，包括改换词性、调整句子重心、拆合句子和消除重复套话。不能删去信息、概括具体经历、补充解释或强化原文。不要把“不增译”理解成“不准润色”。

- 避免日译中常见的翻译腔，例如机械使用“对于……而言”“能够进行……”“有着……”“成为了……”“让人感受到……”等结构。原文简单，就用简单自然的中文表达。

- 注意上下文和说话人的口吻。访谈要像真实的人在接受采访，而不是书面报告；对话要像自然口语；宣传文案可以适当书面，但不要自行拔高。

- 对日语中省略的主语、宾语和逻辑关系，根据上下文判断。只有中文不补就明显不自然时才补，不要加入无法从原文确定的信息。

- 保留原文的模糊性。如果原文本身有多种理解，不要擅自替作者确定一种更具体的意思。

- 对难以直译的表达，优先寻找中文中功能和语气最接近的说法，而不是逐字对应。

- `と思う`、`というか`、`感じ`、`やっぱり` 等不逐次套用固定中文。重复中有犹疑、强调或自我修正时保留其作用；纯属日语句法习惯时可调整。保留“可能”“有一点”等限定，不把推测改成事实。

- 敬语转成适当的中文礼貌程度，不逐层堆叠“承蒙”“能够有幸”“让我得以”。保留原有笑声、迟疑与玩笑，不凭空添加网络梗、卖萌、感叹号或煽情措辞。

- 专业词汇按音乐、录音、表演的具体语境判断，同一语义保持译法一致。歌词、双关和意象保留必要的开放性，不擅自扩写成解说。难以确定且影响理解的疑点在交付说明中提出，不直接塞进正文。

- 导语、署名及说明文字使用清楚的书面中文；不要因其不是问答而漏译。创作者原文确有的抽象和诗性表达可以保留，不强行简化成日常聊天。

- 这是音乐人访谈。请保留受访者实际说话时略带随意、停顿和主观感受的口吻，不要把口语整理成过于完整、正式、漂亮的书面中文。尤其不要为了“高级感”而添加原文没有的抽象词汇。

## 三、执行顺序

1. 通读全文和适合的参考译文，确认说话人、指代、时间与重要术语。排版分块不是语义边界，翻译时要结合前后文。
2. 先完成中文草稿，保持问答与信息点对应，可暂不添加颜色或加粗。不要将逐词直译直接作为成品。
3. 暂时不看日文，连读中文：修正拗口语序、冗余套话、不明指代和不合人物口吻的表达。读者不应需要反推日文才能理解。
4. 重新逐段对照原文，核对遗漏、增译、否定、程度、因果与说话人归属。自然化若改变原意，改成既准确又顺畅的新表达，不简单退回生硬直译。
5. 中文确定后再应用下述排版，最后分别验收语言质量、内容完整性和标记结构。不能以格式正确代替中文质量。

## 四、受保护范围

[original][/original]之间日语文本不可以修改，包括标点、空行和已有格式，以下格式统一需求不适用。

一级标题（#之后的内容），二级标题（##之后的内容），访谈时间&访谈人&出处之后的内容，文本不可以修改，以下格式统一需求不适用

现有单星号斜体说明或图注（如 `*文本内容*`）不可以修改，以下格式统一需求不适用。这不代表新译文中所有加粗片段都不可编辑。

保留图片路径、链接目标、图片位置、原文块顺序和小节结构。中文放在对应原文块前，不集中到全文开头，不为每句话另建原文块。图片与图注放在原文块外，不自行添加小标题、总结或译者评论。用户明确要求修改受保护内容时，以本次要求为准。

## 五、中文排版与专名规范

### 标记细节

- 歌名列表不是穷尽清单。区分乐队 `[c7]Ave Mujica[/c7]` 与歌曲「**Ave Mujica**」，按语义处理，不能只靠文字匹配。
- 提问段已整段加粗时，不在其中嵌套歌名的 `**`，不加人物和乐队颜色。
- 按最长完整名称匹配，已有颜色标签不重复包裹，不生成嵌套颜色。单字“茜”“睦”等只有确实指代人物时才标记。
- 回答人标签沿用文章的全名／简称及分隔方式，同篇保持一致。多人同时回答时分别标记各人，不把组合姓名当作新人物。
- 已有专辑名加粗、歌词颜色和特殊引用格式保留；不要从个别历史格式推导出所有作品名都必须加粗。没有约定的其他人物或乐队不自行分配颜色。
- 中文正文使用中文标点，保留英文专名的拼写、大小写与名称内部空格。禁止用全文替换误改原文、URL、路径或 Markdown 结构。

## 六、交付前核对

- 授权范围内每个待译块都有完整中文，没有遗留占位或漏掉导语、署名、问句、回答、例子与末尾段落。
- 单独读中文，指代清楚、句子顺畅、问答能接上，人物口吻和文本类型有区别。
- 对照日文，事实、否定、时间、数量、因果、比较范围、犹疑及情绪强度一致，没有擅自解释和拔高。
- 将原文块及受保护标题、元信息、图注、图片路径、链接目标与修改前作内容对比，不只检查标签数量。
- 原文标签、颜色标签、加粗标记正确闭合，无重复着色、嵌套颜色、重复 `[br]` 或提问段误着色。
- 本规则本身不授权修改工作簿、构建或发布网站；这些操作按用户任务及相应工作流执行。交付时简要说明完成范围与仍待确认的实质疑点。
