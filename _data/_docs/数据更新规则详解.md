# `data.xlsx` 数据更新规则详解

本文件说明 `_data/data.xlsx` 中每个工作表和字段的作用、显示位置与填写规则。数据改完后，在项目根目录运行：

```powershell
python generate_all.py
```

脚本会更新各页面的 `data.js`、首页的 `announcements.js` 与 `something-new.js`；这些生成文件不要手动修改。

## 通用规则

- **不要改工作表名或第一行字段名。** 生成器以字段名读取数据；改名后对应数据会变为空。
- **空行会被忽略。** 一行只要有任意字段有值就会参与生成，因此请删除不再使用的半空行。
- **日期统一填写 `YYYY/M/D`**，如 `2026/9/16`。`YYYY-MM-DD` 和 Excel 日期也会被规范为这个格式；首页精选会校验日期是否真实存在。
- **文本关联必须完全一致。** 例如 `setlist.live_name` 必须与 `lives.live_name` 完全相同，空格、全半角符号与 DAY 标记也算在内。
- **图片路径通常从项目根目录的 `images/` 开始写**，如 `images/1st live kv.webp`。生成器会自动为子页面加上 `../`。外部 URL 可直接填写。
- **布尔值**：`1`、`true`、`yes`、`y`、`是`、`有`均表示真；其余值和留空均表示假。除非另有说明，推荐填写 `yes` 或留空。
- **列表分隔符不可混用。** 文档会明确标出使用英文逗号 `,` 或竖线 `|` 的字段。分隔符前后的空格会自动移除。
- `hash_id` 不需要填写；它由生成器根据关键字段自动计算。

## 工作表总览与关联

| 工作表 | 对应页面／输出 | 主关联字段 |
| --- | --- | --- |
| `announcements` | 首页公告，`announcements.js` | 无 |
| `something_new` | 首页 Something New，`something-new.js` | `content_type + content_ref` |
| `songs` | Songs 页面，`songs/data.js` | `song_name` |
| `song_comments` | Songs 详情内的制作人讲解 | `song_name` → `songs.song_name` |
| `song_live_history` | Songs 详情的 Live 履历；也为 Setlist 补视频链接 | `song_name`、`live_name` |
| `lyrics_atlas_rules` | Songs 的 Lyrics Atlas 词频规则 | 无 |
| `lives` | Live 页面，`live/data.js` | `live_name` |
| `setlist` | Live 抽屉内的曲目表 | `live_name` → `lives.live_name` |
| `backstage` | Live 抽屉内的返图 | `live_name` → `lives.live_name` |
| `gallery_images` | Gallery 页面 | 无 |
| `timeline` | Timeline 页面，`timeline/data.js` | 同一事件由多个字段自动合并 |
| `interview` | Interview 页面，`interview/data.js` | `title` |
| `discography_releases` | Discography 页面，`discography/data.js` | `release_id` |
| `discography_editions` | Discography 详情的版本页签 | `release_id` → `discography_releases.release_id` |
| `discography_contents` | Discography 详情的曲目／内容 | `release_id`，可再用 `edition_name` 指向版本 |
| `discography_bonus_contents` | Discography 详情的店铺／封入特典内容 | `release_id` |
| 顶部 `SONG` / `LIVE` 对照表 | 当前不由生成器读取 | 仅人工参考 |

## `announcements`：首页公告

每行是一条公告。置顶项保持 Excel 中的顺序；非置顶项按 Excel 从下到上显示，因此最新公告应加在表格底部。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `date` | 首页公告日期 | 建议 `YYYY/M/D`；页面原样显示。 |
| `msg` | 首页公告正文 | 可填写普通文本。 |
| `pinned` | 是否置顶 | 填 `yes` 置顶；留空为普通公告。 |

## `something_new`：首页 Something New

这一表只决定首页要展示哪些已存在内容；标题、封面、副信息和跳转链接都由来源表自动取得。`show` 不为真时，该行不会输出。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `content_type` | 决定来源和跳转页面 | 只能是 `song`、`live`、`interview`、`discography`。 |
| `content_ref` | 查找来源内容 | `song` 填 `songs.song_name`；`live` 填 `lives.live_name`；`interview` 填 `interview.title`；`discography` 填 `discography_releases.release_id`。必须唯一且完全匹配。 |
| `update_date` | 首页排序与 NEW 状态 | 必填；填有效日期。越晚越靠前；改变日期会使已读项目重新被视为 NEW。 |
| `show` | 是否展示 | 填 `yes` 展示；留空可保留记录但暂不展示。 |

## `songs`：歌曲基础资料

每行是一首歌。`song_name` 是与评论、演出履历、首页精选关联的主键，建立后不要随意改名。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `song_name` | Songs 卡片、详情、关联主键 | 建议必填；中文／站内主显示名。必须唯一。 |
| `song_name_jp` | 卡片与详情标题；首页精选标题 | 日文原名；为空时首页精选改用 `song_name`。 |
| `album` | 卡片分组、详情元信息、首页精选副标题 | 专辑／单曲名称。 |
| `album_year` | 卡片分组、首页精选副标题 | 年份，如 `2025`。 |
| `release_date` | 详情、排序、Lyrics Atlas 与统计 | 填有效日期；也参与自动生成的 `hash_id`。 |
| `cover` | 歌曲卡片、详情、首页精选封面 | 建议 `images/...` 路径；留空时显示占位。 |
| `type` | 详情；Lyrics Atlas 的收录范围 | 原创曲必须准确填 `Original`，才会计入 Lyrics Atlas；其他值可按站内显示需要填写。 |
| `lyricist` | 详情制作信息 | 作词者；可留空。 |
| `composer` | 详情制作信息 | 作曲者；可留空。 |
| `arranger` | 详情制作信息 | 编曲者；可留空。 |
| `first_stage` | 详情“首次登台” | 普通文本，如演出全名；可留空或填 `Coming Soon…`。 |
| `mv_url` | 详情 MV 入口 | 完整外部 URL；留空则不显示入口。 |
| `lyrics_jp` | 详情歌词、Lyrics Atlas 日文统计 | 日文歌词；单元格内可用 Alt+Enter 换行。 |
| `lyrics_cn` | 详情歌词、Lyrics Atlas 中文统计 | 中文歌词；单元格内可用 Alt+Enter 换行。 |
| `appearances` | 详情“收录 CD” | 用英文逗号 `,` 分隔多个收录，如 `Alea jacta est,Ave Música`。 |
| `search_keywords` | Songs 搜索 | 补充同义名、译名、罗马字等；用空格分隔即可。 |

## `song_comments`：歌曲制作人讲解

同一歌曲可填多行，页面按 Excel 行顺序显示。若 `song_name` 找不到对应歌曲，该行不会出现在任何详情中。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `song_name` | 关联歌曲 | 必须完全匹配 `songs.song_name`。 |
| `comment_text` | 详情讲解正文 | 可多行填写。 |
| `comment_source` | 讲解来源标签 | 例如媒体或栏目名；可留空。 |
| `comment_from` | 发言者／出处 | 例如作词、作曲者姓名；可留空。 |
| `comment_date` | 讲解日期 | 建议填日期；会被统一格式化。 |

## `song_live_history`：歌曲演出履历

每行代表一首歌在一场 Live 中的一次履历。它既显示在 Songs 详情中，也会在生成 Setlist 时按“演出名 + 歌名”补充视频链接。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `song_name` | 关联歌曲、补 Setlist 链接 | 必须完全匹配 `songs.song_name`。 |
| `live_date` | 歌曲详情履历日期 | 建议 `YYYY/M/D`。 |
| `live_venue` | 歌曲详情履历场地 | 普通文本。 |
| `live_name` | 歌曲详情履历；Setlist 补链接键 | 应与 `lives.live_name` 完全一致。 |
| `has_video` | 详情视频状态 | 填 `yes` 表示有视频。即使 `video_url` 为空也可单独标记。 |
| `video_url` | 详情视频链接；Setlist 自动链接来源 | 填完整 URL。 |

## `lyrics_atlas_rules`：Lyrics Atlas 词频规则

只影响 Songs 页的 Lyrics Atlas，重新生成歌曲数据时生效。规则按 **combine → exclude → similar** 执行；语言填错、功能名不在规定集合或 `terms` 为空的行会被忽略。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `function` | 规则类型 | 只能填 `similar`、`combine` 或 `exclude`。 |
| `jp/cn` | 作用语言 | 填 `jp`、`cn`，或以 `|`、逗号、空格分隔的 `jp|cn`。 |
| `terms` | 被处理的词 | `similar`／`exclude` 用 `|` 分隔同义词或词形；`combine` 用**空格**分隔连续词，例如 `僕 たち`。日文可写 `宇宙（そら）` 以指定读音。 |
| `display` | 合并后显示词 | `similar` 与 `combine` 的显示名；留空时分别使用 `terms` 的第一个词或原文本。`exclude` 不使用。 |

## `lives`：演唱会基础资料

每行是一场演出。`live_name` 是 Setlist、返图、歌曲履历和首页精选的关联主键，必须唯一。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `live_name` | Live 卡片、抽屉、关联主键、首页精选 | 建议必填且唯一；改名时同步修改所有引用它的表。 |
| `live_date` | 卡片日期、排序、统计、首页精选 | 必填；推荐 `YYYY/M/D`。同一演出分日应拆成独立记录。 |
| `live_venue` | 卡片、抽屉、统计、首页精选 | 场地名称。 |
| `poster` | 卡片或抽屉图片 | `images/...` 路径；可留空。 |
| `kv` | 卡片主视觉、首页精选封面 | `images/...` 路径；首页优先用它，留空则改用 `poster`。 |
| `video_url` | 演出视频入口 | 完整 URL；可留空。 |
| `description` | 演出卡片／抽屉说明 | 普通文本；可留空。仅供展示，任何时候都不得用于 Setlist 或 Live 统计筛选；例如“非全场”只表示现存影像不完整，`Opening Act` 仍属于乐队演出。 |
| `live_tag` | Live 页筛选与统计范围 | 现有数据使用 `One Man Live`、`Fes`、`BanG Dream!` 等。相同拼写才会归为同一筛选项。 |
| `for short` | Live Statistics → Setlist Evolution 的列标题 | 演出简称，如 `5th D1`。为空时自动采用去掉 `Ave Mujica` 前缀后的演出全名；鼠标悬停仍显示全名与日期。 |

## `setlist`：演出曲目表

同一 `live_name` 的行按 Excel 从上到下显示。`track_title` 会先按 `songs.song_name_jp` 查找歌曲，再按 `songs.song_name` 查找，以便自动从 `song_live_history` 找到对应视频链接。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `live_name` | 关联演出 | 必须完全匹配 `lives.live_name`。 |
| `track_num` | 曲目编号 | 如 `M01`、`EN01`；间幕可留空。 |
| `track_title` | 曲目名称 | 显示原文。若希望自动找到歌曲履历视频，填歌曲的日文名或 `song_name`。 |
| `highlight_label` | 曲目徽章 | 如 `Live debut`、`COVER`、`Highlight`；留空则不显示。 |
| `highlight_text` | 徽章旁说明 | 普通文本，如翻唱原曲或演出注记；可留空。 |
| `mc_file` | MC／剧情弹窗 | 相对 `_data/` 的 Markdown 路径，如 `mc/0_0.md`。文件不存在时不会显示内容。详见 `md-readme.md`。 |
| `manual_link` | 曲目的手动视频链接 | 完整 URL；优先级最高。留空时依次使用旧字段 `link`（若存在）和 `song_live_history.video_url`。 |

## `backstage`：演出返图

同一演出的图片按 Excel 顺序排列。连续且 `group_id` 相同的图片会合并为一组浏览；留空的 `group_id` 逐张独立展示。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `live_name` | 关联演出 | 必须完全匹配 `lives.live_name`。 |
| `photo` | 抽屉返图 | `images/...` 路径。 |
| `credit` | 图片署名 | 显示摄影者、账号或角色名。 |
| `credit_text` | 图片说明／引用文字 | 支持多行。 |
| `source_url` | 来源跳转 | 完整 URL；留空则无跳转。 |
| `source_label` | 来源按钮文字 | 如 `Source`、`官推`；留空时由同组首张的值兜底。 |
| `group_id` | 多图分组 | 相邻、相同且非空的值会合成一组轮播；建议使用稳定的简短 ID。 |

## `gallery_images`：画廊图片

每行是一张图片，按数据行生成 Gallery 卡片。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `filename` | 图片资源与卡片 | 必填；填写图片相对路径／文件名，按当前 Gallery 的资源约定存放。 |
| `title` | 卡片标题 | 普通文本。 |
| `date` | 卡片日期、排序或筛选信息 | 建议日期格式。 |
| `tags` | Gallery 分类和筛选 | 多个标签用英文逗号 `,` 分隔；层级标签用 `分类:子类`，如 `LIVE:0th,LIVE:1st`。仅填 `LIVE` 会创建无子类的分类。 |
| `description` | 图片详情说明 | 普通文本；可留空。 |

## `timeline`：时间轴事件

没有分组时，`date + title + category + description + tag` 完全相同的行会合为一个事件，适合为同一事件添加多张图／多个媒体。使用分组时，所有相同 `group` 的行会合为一个跨日事件，日期显示为该组最早日至最晚日。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `date` | 时间轴位置与日期显示 | 建议必填并填 `YYYY/M/D`。分组时每一行仍填实际日期。 |
| `title` | 气泡标题与详情标题 | 建议必填。 |
| `category` | 时间轴轨道 | 填 `organization` 显示在左侧 Band 轨；填 `personal` 显示在右侧 Nonrico 轨。 |
| `description` | 展开详情说明 | 支持多行。 |
| `tag` | 气泡图标与筛选标签 | 使用页面已定义的值：`oml`、`bandori_fes`、`fes`、`single`、`album`、`anime`、`offline`、`private`、`business`；留空则无图标。 |
| `media_type` | 媒体类型 | 填 `image`、`video` 或 `link`；留空表示此行无媒体。 |
| `media_src` | 图片／视频地址 | `image` 填 `images/...`；`video` 填视频嵌入 URL。`link` 不使用此列。 |
| `media_caption` | 图片／视频说明 | 仅图片和视频使用；可留空。 |
| `media_url` | 外部链接地址 | 仅 `media_type=link` 时填写完整 URL。 |
| `media_title` | 外部链接显示名 | 仅 `media_type=link` 时填写；留空仍可生成链接，但应填写以便阅读。 |

## `interview`：访谈

每行是一篇访谈。`title` 用于页面打开、首页精选关联与自动 `hash_id`，应保持唯一。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `poster` | 访谈卡片、首页精选封面 | `images/...` 路径；留空会显示占位。 |
| `date` | 卡片日期、排序、首页精选 | 建议 `YYYY/M/D`。 |
| `interviewee` | 卡片与浮层元信息、首页精选副标题 | 受访者姓名；可填多人。 |
| `title` | 卡片、浮层、关联主键 | 必填且唯一。 |
| `md_path` | 浮层访谈正文 | 相对 `_data/` 的 Markdown 路径，例如 `mc/访谈标题.md`。找不到文件时可打开条目，但正文为空。Markdown 写法见 `md-readme.md`。 |
| `if_translated` | 浮层“原文显示”控制 | 只能填 `yes` 或 `no`；其他值会在生成时按 `no` 处理。`yes` 表示内容含翻译，可使用原文显示切换。 |

## `discography_releases`：发行作品主表

每行是一张发行作品，`release_id` 是唱片目录全部关联表和首页精选使用的稳定主键。建议使用不会因标题翻译调整而改变的短 ID。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `release_id` | 关联主键、首页精选跳转 | 必填且唯一，如 `ave-musica`；改动时必须同步修改三个唱片子表和 Something New。 |
| `title` | 卡片、详情标题 | 主显示标题。 |
| `title_jp` | 卡片、详情、首页精选优先标题 | 日文标题；为空时首页精选使用 `title`。 |
| `release_date` | 卡片排序、详情、首页精选 | 建议必填，格式为日期。 |
| `type` | 卡片筛选、详情元信息、首页精选副标题 | 当前筛选逻辑将含 `single` 或 `album` 的值归入 CD，精确值 `bluray` 归入 Blu-ray，精确值 `lp` 归入 LP，其余归 Others；推荐统一使用 `Single`、`Album`、`Blu-ray`、`LP`。 |
| `formats` | 详情 FORMAT | 多个格式用英文逗号 `,` 分隔，如 `CD,Blu-ray`。 |
| `label` | 详情元信息 | 厂牌名；可留空。 |
| `description` | 卡片／详情描述 | 普通文本；可留空。 |
| `cover` | 卡片、详情、首页精选封面 | `images/...` 路径。 |
| `search_keywords` | Discography 搜索 | 补充别名、旧译名、罗马字。 |
| `chart_first_day_rank` | 详情销售／榜单区 | 首日排名，按显示文字填写，如 `1位`。 |
| `chart_first_week_sales` | 详情销售／榜单区 | 首周销量，按显示文字填写。 |
| `chart_first_week_rank` | 详情销售／榜单区 | 首周排名。 |
| `chart_total_sales` | 详情销售／榜单区 | 累计销量。 |
| `chart_source` | 榜单信息来源 | 普通文本或来源说明；可留空。 |

## `discography_editions`：发行版本

每行是一种版本。只有在此表存在 `release_id + edition_name` 的记录时，发行详情才会有对应的版本页签。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `release_id` | 关联发行作品 | 必填，完全匹配 `discography_releases.release_id`。 |
| `edition_name` | 版本页签、内容归属键 | 必填；同一发行内应唯一，并与 `discography_contents.edition_name` 完全一致。 |
| `edition_type` | 版本详情 | 如 `通常盘`、`限定盘`；可留空。 |
| `catalog_no` | 版本详情 | 商品编号。 |
| `price` | 版本详情 | 按显示需要填写币种与税务说明。 |
| `cover` | 版本封面 | `images/...` 路径；可留空。 |
| `format` | 版本详情 | 如 `CD+Blu-ray`。 |
| `distribution` | 版本详情 DISTRIBUTION | 发行／流通信息。 |
| `limited` | 版本详情 LIMITATION | 限定说明，如 `初回限定`。 |
| `bonus` | 版本特典清单 | 多项用竖线 `|` 分隔。 |
| `includes_cd` | 版本内容图标 | 布尔值；填 `yes` 表示含 CD。 |
| `includes_bluray` | 版本内容图标 | 布尔值；填 `yes` 表示含 Blu-ray。 |
| `includes_box` | 版本内容图标 | 布尔值；填 `yes` 表示含 Box。 |
| `includes_goods` | 版本内容图标 | 布尔值；填 `yes` 表示含实体周边。 |
| `cover_gallery` | 版本封面图集 | 多图用竖线 `|` 分隔 `images/...` 路径。 |

## `discography_contents`：发行内容／曲目

每行是一项内容。`edition_name` 留空时属于该发行的所有版本；填写时只会出现在该版本的内容区。页面会把“全版本内容”和“当前版本内容”一起显示。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `release_id` | 关联发行作品 | 必填，完全匹配主表的 `release_id`。 |
| `edition_name` | 限定某版本的内容 | 留空表示全版本通用；填写时必须匹配同发行的 `discography_editions.edition_name`。 |
| `disc_no` | 内容分组标题 | 如 `01`、`DISC 1`；相同的 `disc_no + disc_type` 会归为一组。 |
| `disc_type` | 内容分组标题 | 如 `CD`、`Blu-ray`、`DVD`；留空时显示 `CONTENTS`。 |
| `track_no` | 曲目编号 | 如 `M01`、`01`；可留空。 |
| `song_name` | 歌曲链接与显示标题 | 填 `songs.song_name` 可自动链接到歌曲详情；若为空则使用 `content_title`。 |
| `content_title` | 非歌曲内容标题 | 用于影像、MV、特典等；若 `song_name` 为空，页面也会尝试按该标题链接到 Live。 |
| `duration` | 内容时长 | 普通文本，如 `3:45`；可留空。 |
| `note` | 内容备注 | 普通文本；可留空。 |

## `discography_bonus_contents`：发行特典内容

每行是一项特典。此表与版本的 `bonus` 文本清单不同：它用于展示特典内实际收录的曲目／内容。

| 字段 | 用在哪里 | 填写规则 |
| --- | --- | --- |
| `release_id` | 关联发行作品 | 必填，完全匹配主表的 `release_id`。 |
| `bonus_id` | 特典分组键 | 建议填写稳定 ID；留空时自动使用 `disc_name`，再留空则使用 `bonus`。 |
| `disc_name` | 特典分组显示名 | 如店铺特典或特典 CD 名称。 |
| `track_no` | 内容编号 | 普通文本；可留空。 |
| `song_name` | 歌曲链接与显示 | 填 `songs.song_name` 可自动关联歌曲详情。 |
| `note` | 备注 | 普通文本；可留空。 |

## 更新前检查清单

1. 新增歌曲、Live、访谈或发行作品时，先填主表，再填依赖它的关联表。
2. 检查所有 `song_name`、`live_name`、`release_id`、`edition_name` 的拼写完全一致。
3. 确认新增图片已放入 `images/`，并且路径使用正斜杠 `/`。
4. 运行 `python generate_all.py`，处理控制台中关于 Something New、访谈翻译值或缺失引用的警告。
5. 刷新页面并检查新增卡片、详情与首页入口。
